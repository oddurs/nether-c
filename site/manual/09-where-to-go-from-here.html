Where to go from here

You have buried four programs, given one of them a disk, given another two different environments, replayed a trace with the world switched off, and been refused by the type system for looking at something from the wrong depth.

That is the short path. Here is the rest of the map.

The specification, in a useful order

It is not long and it is not a reference manual you dip into. Read these four, in this order, and you have the language:

§0Overviewthe argument, in two pages
§1Stratathe nine, and why depth composes
§2Calculuseleven rules, one page
§6Evaluationwhat burial actually does

§2 is the one to sit with. Everything the language does is a consequence of eleven rules that fit on a page, and the page being one page is a constraint the project holds itself to rather than a thing that happened to work out.

Then, as you need them:

  • §5 — types, shades, refusals, and why a loop body comes after itself
  • §7 — what a node is, what a trace holds, how provenance is read backwards
  • §8 — every rite, every flag, every exit code
  • §9 — the prelude, function by function, with the stratum of each
  • §10 — the vocabulary, which is not decoration
  • §90 — the rejected alternatives, which is the only honest part of any design document

Rites this manual did not use

nether graft substitutes an answer for an open hole in a trace and re-buries only what changed, which is the operation a build system wants and the reason content addressing earns its keep. It is §8.7: --replace names a hole the trace still has, and refuses an answer already given because that answer belongs to the earlier trace before exhumation.

The three questions people ask

Where is main? There isn't one. There is demand, and a program is the set of things that were demanded and whatever those need. See §4.

How do I print something? You do not. You deposit it and somebody lamps it afterwards. If that feels like a missing feature, chapter 1 is the argument for why it is the point.

How do I run it? You do not, and nether run exists solely to say so and exit 64. It is frozen in §8.0 alongside the canonical value and node encodings (§7.1 and §7.3.1). Everything else in this draft may change without a version bump. Those will not.

Inspecting a trace in the browser

The repository includes the Necropolis, a local WebAssembly trace browser under web/necropolis/ that buries source inside the browser with no server and no world capabilities. From a checkout, run scripts/task wasm && scripts/task serve and open /web/necropolis/.

If you want to work on it

CONTRIBUTING.md is the process and CLAUDE.md is the standard. The roadmap is generated from cairn/items/, one Markdown file per item, and every item carries a proof — the observable fact that settles whether it is finished. "The code exists" is not a proof.

The specification comes before the compiler. If you are about to implement something spec/ does not describe, the section is the first pull request.

One last thing

Everything you read in this manual was executed to produce it. Every $ line on these ten pages runs on every build of this project, in a scratch directory with these programs in it, and the output underneath is compared to what came back. Two bugs were found writing it, and they are 0273 and 0274.

Documentation that lies fails the build. That is not a policy; it is tests/transcripts/run, a single standard-library Python harness that runs on every build.
