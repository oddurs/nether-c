## Measured

`CLAUDE.md` bans attributing work to a tool, a model or an assistant, and says
the `commit-msg` hook rejects it. The hook matched a vendor or model name only
on a co-authorship trailer, plus a robot emoji and two stock phrases. Seven shapes were tried and six went through:

| shape | before |
| --- | --- |
| a co-authorship trailer naming a model | refused |
| a session trailer naming a model | passed |
| a session link in the body | passed |
| an "assisted by" trailer | passed |
| a "generated by" trailer | passed |
| a sign-off naming a vendor | passed |
| prose crediting a model | passed |

The two that passed most easily are the two a tool adds by default: a session
trailer and a session link.

## And nothing checked what was already here

A hook runs on a message being written. Nothing looked at the tree, the items,
the specification, or the commits already on a branch — so the rule covered
what came next and not what was there.

The repository is in fact clean: a hundred and sixteen commits, every pull
request body, every comment, no releases, and every occurrence of the word is
the filename `CLAUDE.md` being cited. That is worth keeping rather than
re-establishing by hand.

## What it cost to write this down

The first draft of this item quoted the seven shapes literally, and the check
refused it — correctly, because a repository holding a working attribution
string is a repository holding one. Naming them is enough.
